Kara Tasks sorting, completed filter, and icon repairs

Implementation
- Added four stable task view sort modes: creation date newest-first (default),
  due date earliest-first with undated tasks last, priority P3 to P0, and
  case-insensitive name A–Z. Equal keys preserve the task document's relative
  order. Completed tasks follow the same ordering and are no longer grouped at
  the bottom.
- Added a native sort dropdown and labeled Show Completed checkbox beside the
  Tasks page heading. Show Completed defaults to checked. Unchecking it filters
  completed rows out of the current Inbox, Today, or named-list view without
  deleting or moving them. Both preferences save immediately and persist across
  restarts.
- Kept Today membership unchanged: tasks with valid due dates on or before the
  local current date remain eligible; future and undated tasks remain excluded.
  Calendar remains its existing placeholder.
- Added optional `created_at` timestamps to newly created tasks at nanosecond
  resolution. Legacy tasks keep `created_at: None`; the application does not
  guess historical times. In Creation date mode, timestamped tasks sort newest
  first and unknown-time tasks follow them in their existing relative order.
- Replaced Inbox's generic icon with a bundled symbolic inbox tray, added a
  bundled symbolic calendar-check icon for Today, and added a bundled list-plus-
  pin glyph for pinned sidebar lists. Existing Calendar icon and sidebar layout
  remain in place. Assets are embedded, theme-tinted SVGs; pin/unpin still
  rebuilds the sidebar immediately.
- Task view sorting only orders references in memory. It does not edit task
  records or Matrix ordering indices.

Storage compatibility
- Extended the existing atomic JSON document to version 5 with optional task
  creation timestamps and persisted sort/show-completed preferences. Missing
  preference fields default to Creation date and Show Completed enabled.
- Version 4 documents load with unknown creation times and default preferences.
  Before the first write upgrades v4 data, Kara writes and verifies an exact
  recoverable copy at `tasks.json.pre-tasks-v5.bak`; the data replacement remains
  atomic. Earlier v1–v3 migrations retain their established exact backup path.
- Migration tests use temporary fixture copies only; no user task file was
  opened or modified during testing.

Known limitations
- Legacy tasks have no known creation time and sort after timestamped tasks in
  their prior document order when Creation date is selected.
- The existing Calendar page is still a placeholder and is not part of the task
  view sorting/filter controls.
- Actual icon sizing, theme tint, toolbar fit, and checkbox/dropdown interaction
  need CachyOS COSMIC graphical review.

CachyOS COSMIC acceptance checklist
1. Launch the build with a temporary XDG_DATA_HOME. Confirm the sidebar keeps
   its existing structure; Inbox shows a tray icon, Today shows a calendar with
   a check, Calendar retains its existing icon, and pinned named lists show a
   small pin beside the list glyph. Pin and unpin lists and confirm the icon
   changes immediately and still respects collapsed-list visibility.
2. In Inbox and a named list, create tasks with different creation times,
   due dates, priorities P0–P3, mixed case names, equal sort keys, and no due
   date. Check each selector choice: newest-first creation date, earliest-first
   due date with undated tasks last, P3-to-P0 priority, and case-insensitive
   A–Z name. Confirm equal keys keep their prior relative order.
3. In Today, verify the existing membership rule remains unchanged: due-today
   and overdue tasks appear; future-due and undated tasks do not. Exercise all
   sort choices and confirm task assignment and Matrix placement do not change.
4. Confirm Show Completed starts checked. Uncheck it in Inbox, Today, and a
   named list: completed tasks should disappear from that view only, with no
   deletion or movement. Recheck it and confirm completed tasks return in the
   selected sort position, remain muted/struck through, and have no Completed
   subsection. Toggle task completion and confirm the view updates immediately.
5. Restart Kara and confirm both preferences persist. Confirm a newly created
   task remains newest in Creation date mode after restart and after editing.
   Verify existing legacy tasks retain their relative order without a fabricated
   creation date. Inspect a disposable copy if validating the v4 upgrade and
   confirm the `.pre-tasks-v5.bak` file exactly matches the original JSON.
6. Check normal and narrow window sizes, light and dark themes, dropdown and
   checkbox keyboard navigation/focus, icon clarity/tint, toolbar alignment,
   and that long list labels and task controls do not clip or overlap.
