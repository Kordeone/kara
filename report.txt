Diagnosis and limits of the evidence
- The former layout regression used an iced button substitute and did not test
  AppModel::nav_bar() inside the real COSMIC frame. It was insufficient evidence
  for claiming the owner-visible layout was correct.
- Before changing production code, measured 910d3cc's actual COSMIC widget tree
  with the locked software renderer. Both standalone sidebar and full frame
  measured: sidebar 280, header 280, inner row 264, four 60px cells, three 8px gaps.
  The reported large unused right area was not reproduced on headless Debian.
- Consequently the precise cause of the CachyOS discrepancy is unconfirmed.
  A runtime/backend difference or a different running binary remains possible;
  neither is asserted as fact. The owner declined further runtime observations.
- The update removes reliance on inferred FillPortion cell allocation and makes
  the header and each cell explicitly match the width allocated by native layout.
  It does not claim that automated measurements prove CachyOS visual approval.

Implementation
- Native responsive widget receives the sidebar's final bounded allocation.
  Header width is exactly that allocation. With native spacing p used for both
  padding and gaps: inner width = allocation - 2p, cell = (allocation - 5p) / 4.
- Four fixed measured cell widths plus three gaps span the entire inner row.
  Icons remain centered horizontally/vertically and each cell is a button.
- The sidebar retains its existing intrinsic minimum spacer and 280px desktop
  maximum. No forced wider sidebar, new navigation structure or pointer tracking.
- Selected cells use an opaque blend of the native primary surface and accent
  (22% accent at rest, 30% hovered, 36% pressed), a restrained 1px accent border
  and native small rounded corners. Native keyboard outline remains distinct.
  Icons use the theme foreground; tests require 4.5:1 contrast for selected,
  hovered and pressed fills in light/dark/high-contrast themes.
- Tooltips remain below the cells; selected accessibility state, module messages,
  contextual subsections and remembered navigation state are retained.
- All other AppModel implementation/handlers/dialogs match 910d3cc byte-for-byte
  after excluding nav_bar() and its new rendering helpers/tests.
- Matrix, neutral drag preview, sorting, task/list CRUD, ordering, persistence,
  tray and single-instance implementation files are unchanged.

CachyOS acceptance instructions
1. Quit Kara through tray Quit, then transfer this exact candidate's source and
   Cargo.lock to a separate CachyOS folder using Samba. Build and launch with
   disposable data (an existing process otherwise receives single-instance Open):
     cargo build --locked
     KARA_SELECTOR_DATA=$(mktemp -d)
     XDG_DATA_HOME="$KARA_SELECTOR_DATA" ./target/debug/kara
2. In a wide window, compare the sidebar edges with the selector: only normal
   padding and three even gaps should remain. The fourth cell must reach the
   right inner edge; no large blank right area. Check long named lists too.
3. Click each cell near both edges, not just the icon. Confirm full-cell hit areas,
   centered glyphs, correct module and unchanged contextual navigation/state.
4. Selected cell must show a clear, restrained rounded rectangular fill over its
   entire area. Hover it and other cells; verify hover differs from selection.
   Tab/Shift+Tab must show an additional focus outline, with keyboard activation.
5. Check bottom tooltips, wide/narrow windows, maximization, sidebar hide/show,
   condensed navigation, light/dark themes and display/app scaling. Confirm no
   header obstruction, collapse, clipped controls or wider sidebar.
6. Smoke-test Matrix list selection, neutral drag badge, destination highlight,
   exact insertion, cancellation, completed movement and keyboard fallback.
   Quit/relaunch with the same data directory to verify saved priority/order.
7. If the unused-right-area symptom remains, capture the whole window and running
   build identity/scaling. Automated layout passing cannot resolve that runtime
   discrepancy without observation; do not promote based on these tests alone.
