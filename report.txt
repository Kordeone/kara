Technical approach
- Uses the locked libcosmic DndSource and DndDestination widgets and iced MIME /
  Move-action negotiation. No custom D-Bus, backend fork or new DnD library.
- A small grip handle starts a native drag after the widget's 8px threshold.
  Checkbox, flag selector and edit/order buttons retain their own normal input.
- Dropping onto a task inserts before that task, shown by a 2px system-accent
  line. Dropping on a quadrant header/background appends within the moving
  task's active/completed block; the quadrant outline highlights that target.
  The source row is outlined and native grab/move cursor feedback is retained.
- Active tasks stay ahead of completed tasks. Before-task drops across that
  completion boundary are invalid. Use quadrant header/background to append a
  completed task after other completed tasks or an active task before them.
- Existing four-quadrant layout, task details, completion styling and accessible
  priority chooser/Up/Down controls remain. Edit/Up/Down are now a compact group
  at the far right of the full-width row; the old 640px row cap is removed.

Reliability and data safety
- Private MIME payload contains only task ID and per-drag token, not task notes
  or a task copy. Only an in-process drag session with an unchanged source
  snapshot and matching current list can authorize a move.
- Source start, hover, finish and cancellation never mutate records. A physical
  drop must be observed, followed by valid Move data for the same placement and
  token. Data is consumed once. Wrong MIME/actions, malformed/oversized data,
  stale sessions/tasks, changed list scope, invalid anchors, canceled gestures,
  duplicate deliveries and self/no-op drops cannot create or delete records.
- Native source Finished can precede destination data; an already-observed
  physical drop remains pending for that delivery. Finished without a drop
  clears the session. Cancellation always invalidates the session.
- Locked DndDestination routes by numeric widget IDs even for named widgets.
  The implementation retains actual source/target IDs across view rebuilds so
  indicator redraws do not invalidate the current offer. Tests verify this.
- The locked scrollable translates child drop rectangles but does not clip
  them. A Matrix-only wrapper intersects them with each visible scroll viewport,
  including the outer narrow/short grid scroller. Off-screen rows cannot steal
  drops. The wrapper forwards keyboard operations, overlays, events and a11y.
- The wrapper names iced_accessibility directly to preserve the native a11y
  return type. That package already existed in Cargo.lock through libcosmic;
  the lock change adds only Kara's dependency edge, with no changed packages,
  versions, sources or checksums. No dependency download/upgrade was required.
- The movement helper validates the position before mutation, changes priority
  plus source/destination ranks together and never rearranges the task vector.
  IDs, titles, completion, dates, notes, creation time and list IDs are preserved.
- Store moves work on a clone and use the existing validated/synced atomic JSON
  replacement. Write errors remain visible and retain prior live/disk state.
  No-op drops avoid a save. Only affected groups' rank values change; existing
  persistence normalization remains idempotent for other canonical groups.
- Existing schema v6, migrations/backups, Tasks sort/direction/Show Completed
  preferences and list behavior remain. Tests use disposable temporary files;
  no personal task data was opened or changed.

CachyOS acceptance steps (after coordinated integration)
1. Quit Kara through the tray. Transfer the coordinated source and Cargo.lock
   through Samba. Build/launch without installation using disposable data:
       cargo build --locked
       KARA_DND_DATA=$(mktemp -d)
       XDG_DATA_HOME="$KARA_DND_DATA" ./target/debug/kara
   Keep KARA_DND_DATA for restart tests; quit existing instances before launching
   a different binary because single-instance activation otherwise restores it.
2. Open Matrix through the existing navigation and select Inbox/Work scopes.
   If the reported contextual sidebar prevents reaching Matrix/selecting lists,
   record the inaccessible control and screenshot. This milestone intentionally
   does not fix it; the owner must coordinate that separate navigation repair.
3. Create several active tasks per quadrant and some completed tasks in Work
   and Inbox, using existing editors. Confirm Edit/Up/Down are at the far right
   at wide/narrow widths and existing flag/arrow keyboard movement still works.
4. Drag only from a grip. Verify threshold, grab/move cursor, source outline,
   subtle insertion line and quadrant highlight using current theme colors.
   Drop before the first/middle task and on header/background to append. Repeat
   upward/downward within a quadrant and across all priorities. Confirm exact
   indicator position, correct priority/flag and no duplicate/lost records.
5. Drag completed tasks before other completed tasks and between quadrants.
   They must remain completed and follow active tasks. Drop across an active/
   completed before-row boundary: no data change. Reactivate afterwards and
   confirm original context and normal completed/active grouping are preserved.
6. Press Escape during a drag, release outside the window, drop on sidebar or
   outside any target, click a grip without dragging, and attempt an invalid
   destination. Verify all task fields/order remain unchanged. Try repeated
   moves and rapid successive drags; no stale indication or duplicate move.
7. Populate quadrants enough to scroll. Pre-scroll to middle/bottom and verify
   drops hit visible rows, not clipped rows above/below. Repeat with the outer
   grid scroller in narrow/short windows, long titles and display scaling. Check
   native priority popovers/checkbox/edit still operate without starting drags.
8. Test in light/dark themes with mouse and trackpad. Verify independent task
   scrolling, accessible flag/arrows and focus visibility. There is no new edge
   auto-scroll feature; pre-scroll a target or use the keyboard fallback for
   positions that are off-screen during the native drag.
9. Quit/relaunch with the same XDG_DATA_HOME. Verify priority, rank, completion,
   IDs, list assignments, notes/dates/creation times persist. Tasks sort/filter
   preferences and original document order must remain unchanged by Matrix
   reordering. Smoke-test task/list CRUD, tray Open/Quit and repeated launch.
10. On disposable copied data only, induce a save failure (unwritable directory
    or an external file change) and drop a task. Expect the visible storage
    error and unchanged task records; resolve the error and retry normally.
