Kara — Stage 2: Named Task Lists

Implementation
- My Lists now provides create, rename and confirmed delete actions, an
  overview and empty states. Named lists appear as native indented sidebar
  entries under My Lists and display their incomplete tasks when selected.
- List IDs are random 128-bit identifiers independent of names. Names are
  trimmed; blank names and duplicates after Unicode lowercasing are rejected.
- The existing task editor gains a List selector with Inbox (no list).
  New tasks in a named-list view default to that list; creation elsewhere
  defaults to Inbox. Moving tasks edits their existing records and IDs.
- Completion retains the assignment. Today and Completed still span all lists.
  Deleting a list clears every associated task's assignment in the same save;
  incomplete tasks appear in Inbox and completed tasks stay completed.
- Native dialogs, existing theme/layout and visible error handling retained.
  Task-editor visual polish remains deferred. No dependencies were changed.

Changed files
- src/tasks.rs: list model, name/reference validation, named-list filtering.
- src/storage.rs: versioned list definitions, legacy compatibility, atomic
  list/task mutations and persistence/failure tests.
- src/app.rs: sidebar lists, list dialogs/actions, task selector/defaults,
  selection preservation and headless navigation/default tests.
- report.txt: this Stage 2 report (Stage 1 report remains in Git history).

Storage compatibility and safety
- Same XDG data location and tasks.json file as Stage 1. Schema version 1
  loads automatically without rewriting the file. The next accepted mutation
  atomically writes schema version 2 with both tasks and list definitions.
- All existing task fields and IDs are preserved. Legacy reserved list IDs
  receive recovered list definitions with the same IDs, preserving assignment.
- Version 2 rejects dangling references, invalid/duplicate list definitions,
  invalid tasks and unknown fields. Unsupported versions and corrupt files
  are preserved with visible errors and disabled mutation controls.
- Existing session locking, snapshot conflict detection, synced temporary
  files, atomic replacement and directory syncing remain in place.
- Failed writes retain the previous in-memory document and original disk
  contents. Editor drafts retain their IDs for retry. As in Stage 1, a sync
  failure after replacement explicitly reports uncertain durability.
- Schema version 2 is not readable by the older Stage 1 binary; do not downgrade
  against the upgraded file. Back up personal data before target-machine trials.

CachyOS COSMIC acceptance steps
1. Transfer source via the existing Samba workflow, retaining Cargo.lock.
   From the transferred project run cargo run --locked. No installation needed.
   For isolated testing, close other Kara instances and launch from one shell:
       KARA_STAGE2_DATA=$(mktemp -d)
       XDG_DATA_HOME="$KARA_STAGE2_DATA" cargo run --locked
   Reuse the same variable for restart checks (single-instance activation applies).
2. Open My Lists, create Work and Home, and reject blank/" work " duplicates.
   Select Work in the sidebar; add a task and confirm its List defaults to Work.
   Create a task from Today/Inbox and confirm the default is Inbox instead.
3. Move the same task Work -> Home -> Inbox using its editor. Check that only
   the destination incomplete view contains it. Set due today/overdue and
   verify Today includes it regardless of assignment.
4. Complete a list task, edit it in Completed and verify the assignment remains.
   Rename its list and verify the sidebar, heading and selector update while
   keeping the task association. Cancel a list rename/deletion to check no save.
5. Confirm deletion of a list containing incomplete and completed tasks.
   Confirm no tasks disappear: incomplete ones return to Inbox; completed ones
   remain in Completed and return to Inbox if uncompleted. Check the empty
   list overview, an empty list view, and the three module placeholders.
6. Restart with the same data directory. Verify names, stable IDs, task moves
   and deletion survive. Check Tab/Enter/Escape, scrolling, narrow windows and
   current COSMIC theme; task-editor visual polish is outside this milestone.
7. With Kara closed, test a COPY of Stage 1 tasks.json in an isolated XDG
   directory. Launch, verify old tasks, add a list, restart and inspect the
   version 2 JSON. Use disposable files to test malformed JSON and a version 2
   task referencing an unknown list: expect a visible error and unchanged bytes.

Limitations and delivery
- Lists are always visible under My Lists, using the existing native sidebar's
  indentation model; this version of the navigation widget has no tree expander.
- No new sorting, list reordering, bulk moves or UI redesign is included.
- Stage 1 limits remain: calendar dates only, English UI, small synchronous
  local JSON saves, and no coordination with external editors ignoring locks.
- Board, Matrix, Pomodoro, tray, autostart, subtasks, tags, recurring tasks,
  reminders, themes, packaging and installation remain outside this stage.
- Repository began clean at b8a608e. A fresh fetch confirmed Stage 1 on GitHub.
  Commit/push outcome is reported separately in the final delivery response.
- No implementation blockers. CachyOS graphical validation remains pending.
