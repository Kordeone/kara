KARA — Calendar Stage 1: Functional Month View

Integration and scope
- Clean main was fast-forwarded from 7259a39 to accepted UI commit 716cf96.
  Baseline formatting, check, strict Clippy, tests, build and private D-Bus
  regression passed (101 regular tests plus 1 separately exercised bus test).
- Calendar development is isolated in /home/rapper/projects/kara-calendar on
  feat/calendar-month, based on 716cf96. No Calendar merge or push was performed.
- Original rescue checkout, other worktrees, branches and backups are preserved.

Implementation
- Five top modules: Tasks, Calendar, Board View, Eisenhower Matrix, Pomodoro.
  Calendar uses the owner's existing bundled Tabler calendar-month.svg. The
  accepted selector, selected-cell background, hover, focus and tooltips remain.
  Five cells share the measured inner sidebar width without widening the panel.
- Calendar is removed from the Tasks sidebar. Inbox, Today, Lists, sorting and
  pinned-list behavior remain. Calendar has Month (all lists), a Lists heading,
  Inbox and the existing named lists as mutually exclusive calendar filters.
  Week and Day entries are deferred rather than displaying fake views.
- Native month grid with Monday–Sunday columns and complete 4/5/6-week rows,
  adjacent-month dates, month/year heading, previous/next and Today controls.
  Current day has an accent border; selected day has an accent border and theme
  surface. Day buttons expose full dates, task counts and state in their names.
- Date cells show up to two compact task previews, priority flags and +N more.
  Selected-day details show every matching task in a scrollable list, including
  reversible completion and access to the accepted task editor. Completed tasks
  are muted/struck through and follow active tasks, without reordering records.
- Add task preselects the selected civil date, selected named list (or Inbox for
  Month/all lists and Inbox), and normal P0 defaults. Generic Add uses the same
  handler. Editing, completion and saving use existing task IDs and Store APIs.
- Wide content (at least 950px) places selected-day details beside the grid;
  narrower content places details below it. Overall scrolling keeps dates and
  details accessible in short windows; details also scroll independently.
- Calendar filters, month and selection are session state. Switching modules
  remembers Calendar context; deleting a shared list safely resets its filter.
- Civil dates use Jiff Date throughout. Today uses the local timezone; no UTC
  conversion is applied to due dates. Undated tasks appear on no calendar date.

Changed files
- src/calendar_month.rs: civil-date state, complete-week calculations, shared
  task filtering and creation draft defaults, with focused unit tests.
- src/calendar_view.rs: native calendar grid, controls, selected-day details,
  theme styling, responsive scrolling and real-widget layout regression.
- src/app.rs: fifth module, contextual navigation, shared editor dispatch,
  deleted-filter recovery, application regressions and five-cell geometry tests.
- src/main.rs: registers the two Calendar modules.
- report.txt: this consolidated milestone report.

Compatibility and preserved behavior
- No new schema, migration, dependencies, database or separate task records.
  JSON remains version 6 with existing atomic writes and corruption protection.
- Cargo.toml/Cargo.lock, task/storage modules, Matrix/DnD modules, tray/lifecycle,
  branding and icon assets are unchanged. The accepted dialog implementation
  matches main byte for byte; its date picker, validation and layout are intact.
- Tests use temporary data only. Existing user task data was not opened or changed.
- Tasks sort preferences and Show Completed setting are not modified by Calendar;
  Calendar deliberately displays completed dated tasks with reversible controls.

Known limitations
- No graphical verification was performed on Debian. CachyOS acceptance pending.
- Month/day labels are currently English; weeks always start Monday. There is no
  existing reliable locale week-start preference in this application to reuse.
- Week/Day layouts, external calendars, recurrence, scheduling times, Calendar
  drag-and-drop, Backup/Restore, Board and Pomodoro functionality are out of scope.
- Selection/filter/month are not persisted. Month defaults to the local current
  date on a new process. Long preview titles are compact; full titles are in the
  selected-day details/editor. Narrow/short windows may require vertical scrolling.

CachyOS launch and acceptance checklist
1. Transfer the Calendar feature source using the established Samba workflow.
   Fully Quit any existing Kara via its tray before launching this build, so
   single-instance activation cannot restore an older binary. In that source
   directory run cargo build --locked, then cargo run --locked. No installation.
   For isolated graphical test data, first choose a fresh directory, e.g.
     KARA_CALENDAR_DATA="$(mktemp -d)"
     XDG_DATA_HOME="$KARA_CALENDAR_DATA" cargo run --locked
   Reuse that same directory for restart checks; do not delete real Kara data.
2. In light and dark COSMIC themes, verify five evenly distributed icons, full
   selected cells, hover, keyboard focus and tooltips. Confirm Tasks has Inbox,
   Today and Lists only; named/pinned lists and sorting retain accepted behavior.
3. Open Calendar. Verify local month/year, Monday-first alignment, correct current
   day border and clear selected day. Navigate December/January, February 2024
   (29 days), February 2025 (28 days), and months requiring six complete weeks.
   Click adjacent-month dates; verify displayed month and selected date change.
   Today must return to the local current date without timezone shifts.
4. Select Month for all lists, Inbox and multiple named lists. Create tasks from
   dates in each filter. Verify the accepted dialog's date/list defaults and P0,
   date picker, shortcuts and validation. Cancel once and confirm no new record.
   Add an undated task in Tasks: it must not appear on arbitrary Calendar dates.
5. Put many tasks on one date. Verify two previews and +N more, full scrollable
   selected-day list, correct titles/flags and no lost or duplicate tasks. Edit a
   title, date, priority and list using the shared editor; check immediate changes
   in the grid, Tasks and Matrix. Complete and uncomplete a task from Calendar;
   confirm muted strikethrough, retained identity/list and Matrix classification.
6. Test maximized, normal, narrow and short windows, including 640x560 application
   size. Check equal date columns, readable controls, selected-day details moving
   below the grid, and all dates/tasks/Add reachable by scrolling. Check month
   controls and keyboard navigation with both empty and heavily populated dates.
7. Rename/delete a filtered list in Tasks. Calendar must show the updated name or
   return safely to Month/all lists; deleted-list tasks remain in Inbox. Switch
   modules and confirm Calendar date/filter remain during the session.
8. Quit/relaunch with the same test-data directory. Confirm dates, priorities,
   IDs, completion and list assignments persist. Recheck Matrix drag/drop and its
   keyboard fallback, Tasks sorting/pins, About/branding, tray close/open, panel
   recovery and single-instance activation. No graphical acceptance is claimed
   until these CachyOS checks are completed by the owner.
