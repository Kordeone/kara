Kara 0.1 — Stage 1: Tasks Foundation

Implemented
- Native COSMIC sidebar: Tasks, with Inbox, Today, Completed and My Lists;
  Board View, Eisenhower Matrix and Pomodoro show future-stage placeholders.
  Selecting Tasks opens Inbox. My Lists is a Stage 2 placeholder.
- Add/edit dialogs with title, optional YYYY-MM-DD due date, Low/Normal/High
  priority and multiline notes. Empty titles and invalid calendar dates are
  rejected. New tasks are incomplete, Normal priority, and have no list ID.
- Stable random 128-bit task IDs, retained by edits and completion changes;
  optional list IDs are stored and preserved for future modules.
- Completion checkboxes and deletion confirmation. Cancel/Escape discard a
  dialog draft. Title fields receive focus when add/edit dialogs open.
- Inbox contains incomplete tasks without list IDs. Today contains incomplete
  tasks due on or before the local date, including future named-list records.
  Completed contains all completed records. All views share the same records.
  Local date is refreshed on navigation and every 30 seconds.
- Standard libcosmic controls, theme, accent, spacing, typography, scrolling,
  keyboard navigation and appropriate empty/error states. No custom theme.
- Existing About panel retained. Application ID corrected from the template's
  dev.mmurphy.Test to io.github.kordeone.Kara, matching existing resources.

Storage
- Versioned JSON at $XDG_DATA_HOME/io.github.kordeone.Kara/tasks.json.
  When XDG_DATA_HOME is unset, empty or relative, use
  $HOME/.local/share/io.github.kordeone.Kara/tasks.json.
- Automatic save after every accepted mutation. A same-directory temporary
  file is written and synced before atomic rename; the directory is synced
  afterward. Save files have mode 0600; newly created data directories 0700.
- An exclusive tasks.lock session lock prevents cooperating Kara processes
  from writing the same store. The lock is released automatically on exit.
- Malformed JSON, invalid task records, duplicate IDs, unknown fields and
  unsupported schema versions prevent loading and disable mutations. Existing
  bytes are preserved. There is no automatic reset of corrupted data.
- Saves compare the disk contents with the last loaded/saved snapshot and
  refuse to replace externally changed or deleted data. Restart to reload
  an external change. Back up and repair corrupt data before retrying.
- Errors are visible. Failed pre-replacement saves preserve the saved task
  state. Editor drafts remain open on failure. Retry storage rechecks the
  current store; after fixing a transient error, repeat the intended action.
  If directory syncing fails after replacement, the error explains that data
  was written but durability could not be confirmed.

Launch on CachyOS with COSMIC Desktop
1. Transfer the source through the established Samba workflow. Keep Cargo.lock.
   Build on the target machine; a Debian-built binary is not assumed portable.
2. From the transferred project directory run:
       cargo run --locked
   Or build with cargo build --locked, then run ./target/debug/kara.
   No installation is required. Do not run the just install recipe.
3. For isolated GUI testing, close all running Kara instances first (the
   existing template uses single-instance activation). In a COSMIC terminal:
       KARA_STAGE1_DATA=$(mktemp -d)
       XDG_DATA_HOME="$KARA_STAGE1_DATA" cargo run --locked
   Reuse this same variable for every subsequent launch in that terminal.
4. Add an undated task; confirm it appears in Inbox, but not Today.
   Add tasks due yesterday, today and tomorrow using local YYYY-MM-DD dates.
   Confirm Today shows yesterday/today only. Try an empty title and an invalid
   date such as 2026-02-30; expect validation without saving or closing.
5. Edit title, due date, each priority and multiline notes. Reopen the editor
   to verify values. Cancel an edit and verify the original remains. Tab through
   controls, press Enter in title/date to save, and Escape to cancel a dialog.
6. Complete a task from Inbox/Today. Confirm it leaves incomplete views and
   appears in Completed. Uncheck it there and verify it returns as appropriate.
   Cancel one deletion, then confirm another. Check all empty states and the
   four future-stage placeholders. Change system light/dark theme/accent and
   check native appearance. Resize the window and scroll the task list/forms.
7. Close and relaunch with the same XDG_DATA_HOME; verify edits, completion and
   deletion survive. The test JSON is at:
       $KARA_STAGE1_DATA/io.github.kordeone.Kara/tasks.json
   Inspect it while Kara is closed to confirm stable IDs and optional fields.
8. Corruption test ONLY against the disposable directory above, with Kara
   closed and at least one saved task:
       KARA_STAGE1_FILE="$KARA_STAGE1_DATA/io.github.kordeone.Kara/tasks.json"
       cp "$KARA_STAGE1_FILE" "$KARA_STAGE1_FILE.good"
       printf '{broken' > "$KARA_STAGE1_FILE"
       cp "$KARA_STAGE1_FILE" "$KARA_STAGE1_FILE.corrupt"
       XDG_DATA_HOME="$KARA_STAGE1_DATA" cargo run --locked
   Expect a visible error and disabled mutations. Close Kara, then run:
       cmp "$KARA_STAGE1_FILE" "$KARA_STAGE1_FILE.corrupt"
   Expect identical bytes. Restore the disposable test data while closed:
       cp "$KARA_STAGE1_FILE.good" "$KARA_STAGE1_FILE"
       XDG_DATA_HOME="$KARA_STAGE1_DATA" cargo run --locked
   Expect the previously saved tasks to return.
9. Optional transient save-error test in that disposable store: while Kara is
   open, remove write permission from its application data directory, then try
   a task edit. Expect a visible save error and retained draft. Restore the
   directory's write permission, choose Retry storage, then Save again.
   Restart and verify the change. Never do this against personal task data.

Known limitations and remaining manual checks
- CachyOS graphical behavior, focus, scaling, keyboard traversal, appearance
  and Samba transfer have not been exercised in this Debian environment.
- Due dates are entered as calendar dates; no times, reminders or date picker.
  The running Today view may take up to 30 seconds to reflect midnight.
- Stage 1 interface strings are English; the template localization support
  remains in place for a later localization pass.
- Saves are synchronous and rewrite the small local document. This foundation
  targets local personal task lists; it is not a large-dataset storage engine.
- The lock protects cooperating Kara processes. An unrelated editor that
  ignores it must not modify tasks.json during saving; snapshot checks detect
  changes before replacement but do not provide coordination with such tools.
- Existing data is never automatically repaired/reset. Corrupt files require
  a manual backup and repair while Kara is closed.
- Named-list management, Board, Matrix, Pomodoro, tray, autostart, packaging,
  synchronization and system installation are outside this stage.
- No installation or system configuration changes performed.
- Implementation blockers: none. CachyOS functional acceptance confirmed by
  the user; additional UI polish remains deferred.
