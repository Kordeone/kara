Kara — Matrix drag-and-drop visual feedback refinement

Scope and isolation
- Worktree: /tmp/kara-matrix-feedback
- Branch: feat/matrix-dnd-feedback, based on b744b6b.
- The prior isolated Matrix review was a source snapshot, not a Git worktree.
  The reviewed patch was applied only to this new worktree and recorded as
  fe41fe9 (feat: add Kara Matrix drag and drop) before the visual refinement.
- The refinement changes only src/matrix_view.rs and report.txt. Shared main,
  Luna's uncommitted navigation repair and other shared source are untouched.
  No merge, push, installation or system configuration changes were performed.
- This branch contains the committed navigation baseline. It deliberately does
  not include Luna's shared-tree sidebar repair; coordinate later integration.

Visual changes
- The dragged source row receives a restrained system-accent surface tint and
  a 2px accent border, retaining its title, controls and completion treatment.
- A valid hovered quadrant receives a lighter accent tint and border for both
  before-row and header/background targets. Feedback is scoped to the current
  list and active drag session.
- The insertion marker is now a 4px accent bar with 8px end caps. Its fixed 8px
  slot exists while idle too: hover does not shift rows or drop hit boxes.
- The marker appears before the hovered row. Header/background drops append
  within the source task's active/completed group, with the marker at that
  group's end. Empty quadrant markers appear above the empty-state text, where
  the first task will be placed.
- The locked libcosmic DndSource::drag_icon API supplies a native compositor
  preview. Its dimensions are constrained to the drag handle's 24px bounds, so
  the preview is a small themed badge using the existing task priority flag.
  A readable title-card preview would be clipped by this API. The source row
  remains highlighted and readable throughout the gesture. No backend patch,
  dependency change, alternative input path or custom preview window was added.
- Source/destination fills blend existing COSMIC surface and accent colors;
  regular widget styles and completed muted/struck-through titles remain.
- Cancellation and finish use the existing lifecycle. Clearing the session
  removes source/destination feedback; the native backend owns preview cleanup.

Preserved implementation and safety
- Native DndSource/DndDestination, grip threshold, stable numeric routing IDs,
  clipped scrolling drop targets and private MIME/Move negotiation remain.
- No changes to Matrix placement validation, completion boundaries, priority
  transitions, ranks, persistence, task IDs/fields, list scope or Tasks sorting.
- Only an observed physical drop plus matching valid session data can move a
  task. Hover, canceled/invalid/stale/replayed drops never mutate records.
- Existing atomic saves and visible errors remain; existing keyboard flag and
  Up/Down controls and far-right action grouping remain.
- Prior Matrix implementation files are retained in fe41fe9: src/matrix.rs,
  src/matrix_drag.rs, src/matrix_clip.rs, src/storage.rs, minimal app/main wiring,
  matrix_view.rs, report.txt and the existing locked a11y dependency edge.
- No user task data was opened or modified. Regression data uses temp files.

CachyOS visual and functional acceptance
1. Quit the running Kara through its tray before launching another build.
   Transfer this isolated branch's source/Cargo.lock to a separate source folder
   using the existing Samba workflow; do not overwrite Luna's working sources.
   From that folder run:
     cargo build --locked
     KARA_FEEDBACK_DATA=$(mktemp -d)
     XDG_DATA_HOME="$KARA_FEEDBACK_DATA" ./target/debug/kara
   Retain KARA_FEEDBACK_DATA for restart checks. Use disposable or copied data.
2. Open Matrix; create active and completed tasks in Inbox and a named list,
   with enough tasks to scroll. Confirm editing, flags and keyboard arrows work.
   If baseline contextual navigation blocks Matrix/list selection, record the
   exact control and screenshot; sidebar repair remains outside this branch.
3. In light and dark themes (also high contrast and 100%/200% scaling), drag a
   grip. Verify the source row is clearly identified, text remains readable,
   and the small native flag badge follows the pointer without clipping/crash.
   The badge depicts the source priority until the drop; target priority is
   communicated by the highlighted quadrant and its existing heading.
4. Hover each quadrant header, empty body and task row. Exactly the valid
   destination quadrant should have subtle tinted feedback, including row
   targets. Confirm no indicator/row jump or flicker after repeated crossings.
5. Drop before first/middle rows, reorder upward/downward and append via header
   or background. The capped bar must predict the resulting position. Repeat
   with empty quadrants and completed tasks; active tasks remain before completed
   tasks, and cross-completion before-row targets remain invalid.
6. Cancel with Escape, release outside the window or drop on a non-target.
   Source, panel and marker must return to their idle appearance and the native
   badge must disappear. Verify task priority/order and all fields are unchanged.
   Then drag again immediately; no stale highlight, lost task or duplicate move.
7. Repeat in wide, narrow and short windows, with long titles, scrolled quadrant
   content and the outer grid scroller. Only visible rows should receive drops;
   actions remain at the right and keyboard movement remains available.
8. Quit/relaunch with the same XDG_DATA_HOME. Verify priorities/ranks, completion,
   list assignment, notes and dates persist, with no missing/duplicate IDs.
   Smoke-test task editing, list switching, tray Open/Quit and second launch.

Limitations / acceptance gate
- The owner confirmed the prior drag behavior graphically. This visual refinement
  still requires CachyOS acceptance: native preview rendering/cleanup, pointer
  hit areas, actual contrast, scaling and scrolling cannot be proven headlessly.
- Preview is a compact priority badge, not a title card, due to the locked native
  source-size constraint. No drag animations, edge auto-scroll or Matrix redesign.
- Shared main and Luna's sidebar work are preserved for later integration. This
  feature branch is committed separately and is not merged or pushed.
