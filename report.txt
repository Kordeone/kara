Kara — Unified Priority Flag and Matrix Cleanup

Delivery
- Based on main at 62df272. This milestone changes presentation and the compact
  Matrix priority chooser only. No push, installation or further feature work.
- All automated checks passed. COSMIC graphical acceptance is pending; no
  graphical testing was performed on headless Debian.

Changes
- One original bundled 16x16 symbolic SVG flag is embedded at compile time.
  Every level, editor choice, Tasks marker and Matrix flag uses the same asset,
  path, silhouette and size. No Unicode glyph, numeric label or installed icon
  theme lookup is used for the visible priority marker.
- Only flag tint depends on priority: 0 neutral gray, 1 muted amber, 2 blue,
  3 muted red. Existing theme-palette hues and contrast adjustment are retained;
  no global theme or surfaces were customized. Existing tests verify 4.5:1
  contrast against standard COSMIC light/dark/high-contrast content surfaces.
- The editor still has four evenly spaced 36px controls in the accepted layout.
  All show the identical flag. Native IconVertical selected backgrounds and
  keyboard focus styling remain. Full meanings appear in tooltips and names;
  the selected option's accessible name explicitly includes '(selected)'.
  This supplements the pinned native button's accessible name implementation,
  which does not independently announce the selected flag state.
- Shared Tasks markers now show a small flag with a full-meaning tooltip;
  due-date metadata, row structure and completed title styling are unchanged.
  Inbox, Today and named lists use those shared markers. Calendar remains its
  existing placeholder; no Calendar implementation was added or changed.
- Matrix retains the equal-sized quadrants, exact descriptive headings, native
  surfaces, independent task scrolling and narrow/short-window fallback.
  Headers show a restrained matching flag instead of numeric priority text.
- Matrix cards retain completion, title, optional due date, edit and ordering
  actions. Removed the full-width classification dropdown and repeated quadrant
  description beneath each task. There is one small colored task flag beside
  its title; no repeated P0-P3 text or separate priority metadata line remains.
- Activating that flag opens a compact native popover containing the same four
  selected flag buttons as the editor. Choosing one uses the existing Classify
  action and closes the popover. Outside-click dismissal and a Matrix-scoped
  Escape handler are provided. Changing lists or opening a task editor/creation
  dialog clears the chooser. Read-only/storage-error state disables reassignment.

Preserved behavior/data
- Numeric Priority 0..3 mappings, new-task default 0, IDs, lists, completion,
  dates, notes, classification semantics and manual ordering are unchanged.
- Existing editing, Matrix creation defaults, list movement and destination
  append rules continue using the same task records and storage operations.
- src/tasks.rs, src/matrix.rs and src/storage.rs are unchanged. JSON remains
  version 4, with the existing explicit legacy migration and verified original
  backup before replacement. No migration was performed on personal data.
- Existing migration semantics remain: legacy classified tasks take their Matrix
  priority; unclassified Low/Normal/High become 0, with original values retained
  in tasks.json.pre-priority-v4.bak. This milestone adds no migration or format.
- Sidebar/navigation, shared dialog fields/date picker/shortcuts/validation,
  tray/lifecycle, dependency files and deferred modules remain unchanged.
- No sorting, Show Completed, drag/drop, sidebar work, packaging or autostart.

Modified files

CachyOS COSMIC acceptance checklist — REQUIRED
1. Quit all Kara instances via the tray. Transfer current main source through
   Samba with Cargo.lock. Build and launch without installation:
       cargo build --locked
       KARA_FLAG_DATA=$(mktemp -d)
       XDG_DATA_HOME="$KARA_FLAG_DATA" ./target/debug/kara
   Keep KARA_FLAG_DATA for restarts. Single-instance activation would otherwise
   restore an older running binary rather than testing this build.
2. Add Inbox and named-list tasks. The editor must show four identical flag
   silhouettes with gray/amber/blue/red tints, evenly spaced compact targets and
   default 0 selected. Hover each for its full meaning; test Tab/Space/Enter.
   Verify the selected native background remains clear in grayscale as well.
3. Save tasks at all four levels, reopen them and confirm the correct existing
   flag is selected. Verify names with accessibility tooling: one choice must
   announce '(selected)' and every choice must describe importance/urgency.
   Smoke-test the accepted date picker, shortcuts, validation and Cancel.
4. Inspect Inbox, Today (add a due-today task) and named lists: one small flag per
   task, due dates retained, no visible numeric priority metadata. Confirm full
   meaning tooltips and unchanged muted/struck-through completed titles.
5. Inspect Matrix: equal quadrants and descriptive headings remain. Cards must
   have one flag, checkbox/title, optional due date, edit and Up/Down controls;
   no full-width repeated quadrant description or numeric metadata below them.
6. Click a task's flag. Check the compact four-flag popover, current selection,
   tooltips and keyboard access. Choose every destination, including on a
   completed task: its priority/quadrant must update without duplicate records.
   Verify destination append, list identity and ordering; test Escape and outside
   click dismissal, list switching and opening the existing editor.
7. Check empty/populated quadrants, independent scrolling, long titles, sidebar
   visible/hidden, wide/narrow/short windows, display scaling and light/dark
   themes. Confirm flags are recognizable, selected state distinct, popovers
   reachable near viewport edges and task controls neither overlap nor clip.
8. Quit/relaunch with the same XDG_DATA_HOME. Confirm priorities/order/lists and
   edits persist. Smoke-test tray Open/Quit and second-launch activation.

Known limitations
- Tests establish asset identity, mappings, contrast on standard content surfaces
  and data behavior; they do not establish pixel correctness, screen-reader
  output, keyboard focus experience or popup placement on COSMIC.
- Native selected/hover surfaces, unusual customized themes, scaling and nested
  scrolling require the owner's CachyOS visual/accessibility checks above.
- The Matrix chooser is session UI state only. This milestone deliberately
  leaves the accepted dialog layout, Calendar placeholder and data model intact.
