Implemented
- Kept the restored native libcosmic navigation and existing Tasks hierarchy.
  No horizontal four-icon section selector or shell restructuring was added.
- Constrained Tasks and Lists content to a centered 960 logical-pixel maximum.
  Task rows use a narrower 880-pixel maximum while staying fluid at small widths.
- Grouped each task row as checkbox, title and metadata, then adjacent Edit/Delete
  icon buttons. Task title and metadata share a column; action spacing is compact.
  Existing COSMIC symbolic icons, tooltips, selected states, and control behavior
  remain in use.
- Kept active tasks before completed tasks, in their existing contexts. Completed
  titles remain muted and struck through; their checkboxes and actions remain usable.
- Centered empty-state copy within the task-list area.
- Organized the shared Add/Edit task dialog into Task details, Organization, and
  Notes sections. Inputs and dropdowns use available width, validation errors are
  shown above the fields, and the dialog and scrollable form have size limits for
  narrow windows. Add and Edit retain the same fields, defaults, focus, validation,
  save, cancel, task-list assignment, and Matrix compatibility.
- No task/list storage fields, data semantics, Matrix presentation, tray behavior,
  single-instance behavior, or other modules were changed.

CachyOS COSMIC graphical acceptance checklist
1. At a normal window size (about 1280 x 800), confirm the labeled native sidebar
   is unchanged and the Tasks content is centered with a readable maximum width.
2. Inspect Inbox, Today, and a named list. Confirm checkbox, title, due/priority
   metadata, and adjacent icon-only Edit/Delete buttons align consistently.
   Tab through the row and verify both icon buttons are keyboard reachable and
   their tooltips identify the actions.
3. Create active and completed tasks in Inbox and a named list. Confirm completed
   tasks remain in that context, appear after active tasks, have muted struck
   through titles, and remain editable and reversible.
4. Inspect each empty state and verify its message is centered in the task area.
5. Add and edit a task. Verify title, optional YYYY-MM-DD due date, priority,
   notes, and task-list selection; ensure current values are retained on Edit and
   Matrix task creation still opens the same editor with the selected list.
6. Try a blank title and malformed/impossible date. Confirm the error is visible
   above the form fields and the editor stays open. Verify title focus on opening,
   Enter-to-save from text fields, Tab navigation, Escape/Cancel, and Save.
7. At the minimum window size (640 x 560), repeat the dialog and task-row checks.
   Confirm the form scrolls without hiding Cancel/Save, dropdowns remain usable,
   task titles and metadata do not collide with actions, and the content remains
   reachable. Also inspect an intermediate size (about 800 x 600).
8. Verify Lists create, rename, select, delete confirmation, pin/unpin, collapse,
   and pinned-list visibility when collapsed. Confirm the native sidebar labels,
   icons, disclosure, and selected states align in light and dark themes.
9. Smoke-test Matrix Add/Edit and classification retention, then tray close,
   reopen, second-launch activation, and quit to confirm those existing behaviors.
